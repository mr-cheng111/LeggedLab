1. 总览结论
===========

1. 当前项目不是“只改 checkpoint key 名”的直接移植。
   原版是 IsaacGym + legged_gym + 旧版 rsl_rl。
   当前是 IsaacLab + rsl_rl v5 兼容的本地 runner/model/controller。

2. actor 网络的 shape 能对齐，但调用方式不同。
   原版推理调用:
     ActorCriticWMP.act_inference(obs, history, wm_feature)
   当前推理调用:
     WMPMLPModel(TensorDict，其中包含 policy/critic/wmp 观测组)
   converted checkpoint 是把原版权重映射进当前这个新包装结构。

3. World Model 架构参数基本对齐原版 Dreamer/WMP 默认值:
     dyn_deter=512
     dyn_stoch=32
     dyn_discrete=32
     update_interval=5
     prop_dim=33
     WMP action_dim=12*5=60
   但是数据流、replay 实现、在线训练 controller 已经不同。

4. 环境和相机链路是运行时差异最大的部分。
   原版使用 IsaacGym camera sensor，挂在 A1 URDF trunk 上。
   当前使用 IsaacLab TiledCameraCfg / rgbd_camera，支持 partial camera envs，
   并由 IsaacLab sensor update/render 调度控制。

5. converted 原版权重能加载，只说明 actor、world_model、depth_predictor
   的 tensor shape 和 key 映射成功。
   这不保证行为一致，因为 joint order、相机外参、history 时序、domain randomization、
   critic/AMP 状态都可能不同。

6. 如果 converted checkpoint 一运行就“起飞”，最高优先级嫌疑是 joint order。
   原版 A1 URDF 的关节顺序来自原始 URDF，很可能和 IsaacLab A1 USD 的
   env.robot.joint_names 不一致。这个问题会同时影响 joint_pos、joint_vel、
   previous action、WMP prop 和最终 policy action。

3. 文件级差异摘要
=================

3.1 wmp_runner.py vs wmp_amp_runner.py + controller.py
-----------------------------------------------------
原版行为:
  - 单个 WMPRunner 控制 WMP、AMP、PPO、replay、checkpoint 的大部分逻辑。
  - 直接从 dreamer/configs.yaml 构建 WorldModel。
  - 直接构建 ActorCriticWMP。
  - 显式维护 self.trajectory_history。
  - 显式维护 wm_action_history。
  - 使用 env.global_counter % update_interval 决定何时 step RSSM 和存储 WMP 数据。
  - 使用 wm_buffer 保存当前 episode，再把结束的 episode 复制到 wm_dataset。
  - 使用 env.depth_index 将真实相机图覆盖到预测图上。
  - checkpoint key:
    model_state_dict
    optimizer_state_dict
    world_model_dict
    wm_optimizer_state_dict
    depth_predictor
    iter
    infos

当前行为:
  - WMPAMPRunner 是 rsl_rl v5 兼容 runner。
  - WMPTrainingController 管 WMP 时序和 replay。
  - WorldModel 来自 legged_lab.world_models.wmp.config 默认值。
  - actor/critic 通过 rsl_rl v5 model factory 构建。
  - WMP feature 通过 obs["wmp"] 注入 policy。
  - 环境自己维护 actor observation history buffer。
  - Controller.observe_before_policy() 在 WMP tick 更新 RSSM。
  - Controller.after_env_step() 更新 action history、reward accumulator 和 pending WMP obs。
  - 使用 WMPFixedEpisodeReplayBuffer 替代原版 wm_dataset/wm_buffer 数组。
  - checkpoint key:
    actor_state_dict
    critic_state_dict
    optimizer_state_dict
    world_model_state_dict
    world_model_optimizer_state_dict
    depth_predictor_state_dict
    depth_predictor_optimizer_state_dict
    amp 相关状态

兼容性影响:
  - tensor shape 可以映射，但 checkpoint 根 key 和 optimizer state 不能直接互换。
  - 原版 critic 和 optimizer state 与当前 rsl_rl v5 runner 结构不直接兼容。
  - reset、初始 WMP obs、action history 相对 env.step 的时序可能存在细微差异。


3.2 ActorCriticWMP vs WMPMLPModel
---------------------------------
原版 ActorCriticWMP:
  - history_encoder(history) -> latent_dim=35。
  - command = observations[:, privileged_dim + 6 : privileged_dim + 9]。
  - wm_feature_encoder(wm_feature) -> wm_latent_dim=32。
  - actor 输入 = concat(history_latent, command, wm_latent) -> 70 维。
  - act_inference 返回 actor(concat)。
  - actor 自己持有 std 参数。
  - 没有 actor latent obs_normalizer。

当前 WMPMLPModel:
  - 接收 TensorDict observation groups。
  - 将 "wmp" 从非 WMP 观测中分离。
  - 从 actor obs buffer 中重构 history。
  - _extract_history 在 command_start=6 的位置移除 command 维度。
  - _extract_command 从最后一个 history step 提取当前 command。
  - wmp_encoder 将 WMP deter feature 映射到 32 维。
  - A1 WMP 配置下 actor head 输入仍然是 70 维。
  - 使用 rsl_rl v5 distribution/normalizer 接口。
  - converted 原版 actor 会把 obs_normalizer 设置成恒等变换，因为原版没有这个 normalizer。

兼容性影响:
  - actor 权重经过 key rename 后可以兼容。
  - 运行时输入必须保持原版语义：joint order、history order、command 位置、
    WMP feature 类型和 normalization 都要一致。
  - 如果 policy obs 是 env joint order，而原版 actor 学到的是原版 URDF joint order，
    shape 检查不会报错，但动作语义会错。

4. 行为差异
===========

4.1 Observation layout
----------------------
原版 actor command 提取:
  command = observations[:, privileged_dim + 6 : privileged_dim + 9]

当前 actor command 提取:
  command 从最后一个 history step 中提取:
  current[..., command_start : command_start + command_dim]

当前代码只有在 actor history 每步布局保持如下结构时，才能重构相同语义:
  ang_vel(3), projected_gravity(3), command(3), joint_pos(12), joint_vel(12), action(12)


4.2 History 归属
----------------
原版:
  WMPRunner 自己维护 trajectory_history。
  env.step 后 append obs_without_command。
  对 done env 清零 trajectory_history。

当前:
  BaseEnv 自己维护 actor_obs_buffer。
  WMPMLPModel 从 obs["policy"] 中抽取 history。
  Reset 行为取决于 BaseEnv actor_obs_buffer.reset()。

风险:
  如果 buffer reset 填充值或 step 时序与原版 trajectory_history 不一致，
  reset 后最初几秒的行为会不同。


4.3 WMP feature 时序
--------------------
原版:
  if env.global_counter % wm_update_interval == 0:
    encode wm_obs
    obs_step RSSM
    wm_feature = get_deter_feat(wm_latent)

当前:
  observe_before_policy() 检查 step_counter % update_interval。
  如果 pending_obs 为空，会创建 initial WMP obs。
  在 policy 前 encode pending_obs 并更新 latent。
  after_env_step() 在 interval 边界准备下一帧 pending_obs。

风险:
  设计上镜像原版意图，但 counter 来源和初始 pending obs 不是完全相同的状态机。


4.4 WMP action history
----------------------
原版:
  wm_action_history 在 policy action 后更新，再 flatten 成 wm_action 并存储。

当前:
  controller.after_env_step(actions, rewards, dones, wm_obs) 在 env.step 后更新 action_history。
  在 WMP tick 存储 flatten 后的 action_history。

风险:
  如果为了兼容原版 policy 做 action reorder，WMP controller 应保存 policy-order actions，
  而 env.step 应接收 env-order actions。当前 play 兼容 adapter 就遵循这个思路。


4.5 Depth image 语义
--------------------
原版:
  IsaacGym IMAGE_DEPTH 是负值。
  process_depth_image 会 clip 到 [-far, -near]。
  normalize_depth_image 公式:
    image = ((-depth) - near) / (far - near) - 0.5

当前:
  IsaacLab distance_to_image_plane 是正值。
  preprocess.depth_to_nchw 同时兼容正深度和负深度:
    depth = where(depth < 0, -depth, depth)
    image = (clamp(depth, near, far) - near) / (far - near) - 0.5

风险:
  公式已对齐，但 renderer、clip 行为、camera frame 和图像刷新时序仍可能不同。


4.6 Camera extrinsics
---------------------
原版:
  position=[0.27, 0, 0.03]
  y_angle=[-5, 5]
  x_angle=[0, 0]
  z_angle=[0, 0]

当前训练配置:
  spawn_offset_pos=(0.3, 0, 0.03)
  random_pitch_deg=(5, 15)

风险:
  原版 checkpoint 应该先用原版 camera extrinsics 测试，而不是使用当前 5-15 度 pitch
  的训练分布。


4.7 Joint order
---------------
原版:
  A1 action 和 joint observation 顺序来自 IsaacGym 载入原版 A1 URDF 后的 DOF names。
  原版 URDF 中 actuated joints 按 FR、FL、RR、RL 的腿块顺序出现。

当前:
  A1 action 和 joint observation 顺序来自 IsaacLab A1 USD 的 env.robot.joint_names。

风险:
  如果 env.robot.joint_names 与原版 policy order 不一致，actor 会输出 shape 正确但语义错误的动作。
  这类问题非常容易导致立即失稳或“直接起飞”。


4.8 Play 阶段 domain randomization
----------------------------------
原版训练:
  使用 action latency 和 motor strength randomization。

当前 play:
  play.py 默认会关闭 push，除非显式开启；但 action_delay 和 motor_strength 是否开启取决于配置，
  除非使用兼容选项关闭。

风险:
  严格调试原版 checkpoint 时，应先关闭 play-time randomization；
  等 nominal behavior 正常后再逐步打开。


5. Checkpoint 兼容风险
======================

CRITICAL
--------
1. Joint order mismatch。
   影响 joint_pos、joint_vel、last_action、WMP prop、actor 输出 action 和 WMP action history。
   shape 检查无法发现这个问题。

2. 当前 converted checkpoint 保留的是 reference critic/AMP/optimizer state。
   推理可以使用 converted actor + WMP modules，但训练续跑不是严格的原版 checkpoint resume。


HIGH
----
3. Camera extrinsics 和 pitch 分布不匹配。
   原版 checkpoint 期望 [0.27,0,0.03] 和 [-5,5] 度 pitch。
   当前 A1 WMP 训练默认是 (0.3,0,0.03) 和 [5,15] 度 pitch。

4. WMP feature 时序和初始/reset history 差异。
   Controller 逻辑镜像原版，但不是同一个对象和状态机。

5. IsaacGym vs IsaacLab 仿真器与资产差异。
   即使 PD scale/stiffness/damping 一样，asset、contact、solver、articulation 实现不同，
   动力学仍可能不同。


MEDIUM
------
6. Depth image renderer 分布。
   归一化公式对齐，但 sensor frame、rasterization、near/far 行为仍可能不同。

7. Terrain generation 和 curriculum。
   原版 WMP terrain layout 与当前 WMP terrain generator 不保证 byte-identical。
   当前项目还增加了训练 terrain curriculum。

8. AMP retarget 和 canonical obs 差异。
   当前 AMP 链路包含 retarget adapter 和 canonical observation 检查。


推理低风险、训练高风险
----------------------
9. WMP 训练超参数改变。
   当前 train_start_steps、batch_size、model_lr 为本地稳定性做过调整。
   这不阻塞推理，但会改变继续训练行为。


6. 建议调试顺序
===============

步骤 1: 验证 converted checkpoint 的 tensor 兼容性。
  使用 inspect_pt_checkpoint.py，并通过 --compare 对比一个当前原生 checkpoint。
  期望 actor/world_model/depth_predictor:
    missing=0
    unexpected=0
    shape_mismatch=0

步骤 2: 使用原版兼容 play 模式运行 converted checkpoint。
  命令:
    ./legged_lab/scripts/play_a1_wmp_visualize.sh original_wmp_converted model_10000_converted.pt 4 original

  该模式应该:
    - 使用 policy_joint_order=original_wmp_a1
    - 关闭 play domain randomization
    - 使用 camera_offset_pos 0.27 0.0 0.03
    - 使用 camera_random_pitch_deg -5 5

步骤 3: 在运行时打印并保存 env.robot.joint_names。
  与原版 A1 URDF joint order 对比。
  如果不同，原版 policy 推理必须保留 joint order adapter。

步骤 4: 先不测复杂地形。
  先用 flat 或低难度地形，把 locomotion/control 兼容性和 WMP terrain perception 分开。

步骤 5: 单独检查 policy 稳定性。
  临时查看 actions 和 processed joint targets。
  检查是否有 action clipping saturation，或明显的错误腿相位。

步骤 6: 单独检查 WMP/depth。
  开启 real/prior/posterior depth 可视化，查看 RSSM prior/posterior error。
  如果平地运动稳定但感知地形失败，下一步重点查 camera/depth 链路。

步骤 7: 稳定推理后再考虑继续训练。
  除非明确对齐 critic、AMP、optimizer、replay、normalization states，
  否则不要把 converted checkpoint 当成完整原版训练状态续跑。

最终说明
========

当前项目可以承载 converted 原版 WMP actor/world_model/depth_predictor 权重，
但它不是同一个 runtime framework。测试原版 checkpoint 推理时，应首先强制原版 joint order、
原版 camera extrinsics，以及干净的 play env。继续训练时，应把 converted checkpoint
视为部分模块迁移，而不是完整训练状态 resume。
